# caelestia dependencies

Stowing this package links `~/.config/caelestia/` (caelestia-cli's `cli.json` and the Hyprland overrides `hypr-vars.lua`, `hypr-user.lua` and `modules/`) and `~/.local/share/caelestia/schemes/` (color schemes generated by `theming/generate.py`). Install the following first.

On `caelestia scheme set`, `cli.json` leaves caelestia writing only Hyprland's `scheme/current.lua`, the GTK 3/4 `gtk.css` and `thunar.css` (plus GTK theme, icon theme and color-scheme in dconf), qtengine's colors and config, the btop theme and fuzzel's colors. Everything else is turned off: terminal recoloring and Vesktop because the repo's Ghostty and Vesktop themes own those, the rest (Chromium, htop, nvtop, cava, Zed, Spicetify, Pandora, Warp) because those apps aren't used. Re-enable a flag there if you start using one.

## Required

| Dependency | Why | Install docs |
|---|---|---|
| caelestia-cli (`caelestia`) | `caelestia scheme set` renders the active scheme into `~/.config/hypr/scheme/current.lua`, which `hypr-vars.lua` reads for border and shadow colors, and into the files listed above; `cli.json` is its config. AUR on Arch | https://github.com/caelestia-dots/cli |
| `hyprland` package from this repo | `hypr-vars.lua` and `hypr-user.lua` are loaded by its `hyprland.lua`; stow that too. Its DEPENDENCIES.md also covers qtengine and the Darkly style, which caelestia's qtengine config selects | [../hyprland/DEPENDENCIES.md](../hyprland/DEPENDENCIES.md) |

Install commands:

```sh
# Arch / CachyOS
yay -S caelestia-cli   # AUR, or any AUR helper
```

## Optional

| Dependency | Why | Install docs |
|---|---|---|
| adw-gtk-theme | caelestia sets the GTK theme to `adw-gtk3-dark` in dconf and layers its `gtk.css` colors on top. Without it GTK 3 apps use stock Adwaita under those colors | https://github.com/lassekongo83/adw-gtk3 |
| `quickshell` package from this repo | Its `config/Colors.qml` reads the active scheme from `~/.local/state/caelestia/scheme.json` and recolors the bar live | [../quickshell/DEPENDENCIES.md](../quickshell/DEPENDENCIES.md) |
| Dolphin (or another KDE app) | Reads some colors through KColorScheme instead of the Qt palette qtengine sets, so it needs a KDE color scheme too. caelestia's `~/.config/qtengine/caelestia.colors` already is one (named `Caelestia`); see After stowing for linking it in | https://apps.kde.org/dolphin/ |
| btop | Uses the `caelestia.theme` caelestia writes to `~/.config/btop/themes/` (`color_theme` in the untracked `btop.conf`) | https://github.com/aristocratos/btop |

```sh
# Arch / CachyOS
sudo pacman -S --needed adw-gtk-theme btop
```

## Verify

```sh
command -v caelestia >/dev/null && echo "caelestia ok" || echo "caelestia MISSING"
caelestia scheme list | grep -q wisteria-dusk && echo "scheme linked ok" || echo "scheme NOT linked (see After stowing)"
[ -d /usr/share/themes/adw-gtk3-dark ] && echo "adw-gtk3 ok" || echo "adw-gtk3 MISSING (optional)"
[ -e ~/.local/share/color-schemes/Caelestia.colors ] && echo "KDE scheme linked ok" || echo "KDE scheme NOT linked (optional, see After stowing)"
```

## After stowing

caelestia-cli only looks for schemes in its own data dir, so link each generated scheme in there (needs `sudo`; redo after caelestia-cli moves to a new Python version), then apply it:

```sh
data=$(python3 -c 'import caelestia, os; print(os.path.dirname(caelestia.__file__))')/data/schemes
for s in ~/.local/share/caelestia/schemes/*/; do sudo ln -sfn "${s%/}" "$data/$(basename "$s")"; done
caelestia scheme set -n wisteria-dusk -f default -m dark
```

After rerunning `theming/generate.py`, setting the same scheme again does nothing: caelestia keeps the colors cached in `~/.local/state/caelestia/scheme.json` until the name, flavour, mode or variant changes. Toggle the variant (ignored by non-dynamic schemes) to reload the file:

```sh
caelestia scheme set -v vibrant && caelestia scheme set -v tonalspot
```

For Dolphin, make caelestia's qtengine colors available as a KDE color scheme and select it in Dolphin's own config. Outside a Plasma session a KDE app ignores `kdeglobals` and only uses a scheme set in its own rc file; the value is the file name without `.colors`. Dolphin picks up scheme changes on its next start:

```sh
mkdir -p ~/.local/share/color-schemes
ln -sfn ~/.config/qtengine/caelestia.colors ~/.local/share/color-schemes/Caelestia.colors
kwriteconfig6 --file dolphinrc --group UiSettings --key ColorScheme Caelestia
# same for other KDE apps, e.g. katerc, okularrc
```
